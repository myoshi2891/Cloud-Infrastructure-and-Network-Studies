# ホーム・グローバルメニューのデザイン設計

## 目的と情報設計

教材が増えても目的の学習パスを見つけられるよう、ホームとメニューで検索・カテゴリ選択の操作を統一する。
ホームは「サービスの目的 → 学習パスの探索 → サイト統計」、メニューは「検索・カテゴリ選択 → 試験・書籍 → 個別ガイド」の順に構成する。

ホームの検索は試験名・略称・説明・レベル・カテゴリ名・ドメイン名を対象にする。カテゴリ選択とキーワードは AND 条件で絞り込む。
件数を読み上げ、該当なしの場合は条件をリセットできる。メニューはカテゴリ・試験名・個別ガイド名から検索でき、検索中は該当するアコーディオンを展開する。

## 表示と操作

- 既存の暗色テーマを継承し、青のアクセント、罫線、余白で情報の優先順位を示す。
- ホームとヘッダーは `--site-content-width` を共通の幅として参照する。
- カードの本文・個別ガイド名は14px以上とし、長いガイド名は折り返して表示する。
- 検索条件は折り返すボタン群にし、カテゴリ数が増えても横スクロールを必須にしない。
- メニューは768px以上で余白のあるパネル、それ未満で全画面表示にする。パネル内だけをスクロールする。
- 閉じるボタンと個別ガイドの操作領域は44px以上を確保する。
- 検索欄を含むフォーカストラップ、Escapeによる閉じる操作、トリガーへのフォーカス復帰を保持する。
- フォーカスを可視化し、OSの動きを減らす設定ではパネルと矢印の動きを抑制する。

## 拡張時の変更箇所

`app/constants.ts` の `ALL_EXAMS` が教材データの正本。公開用の `EXAMS` からホームと `toNavTree` の両方を生成する。
カテゴリ名と順序は同ファイルの `providerMeta` / `providerOrder` に集約し、ナビゲーション側の重複定義を除く。
件数と絞り込みボタンは受け取った教材から生成するため、既存カテゴリへの教材追加でUIの修正は不要。

新カテゴリでは `Provider` 型、`providerMeta`、`providerOrder` と `ProviderMark` を拡張する。
新しい教材テーマを追加する場合は既存のカード色・アイコンの定義も追加する。
メニューもカードと同じ色クラスの `--card-accent` を参照し、メニュー専用のアクセント一覧は持たない。

`CatalogControls` は検索文字列とカテゴリ選択を受け取る表示コンポーネントとし、検索対象と状態の管理はホーム・メニューそれぞれに置く。
将来、レベルや学習形式の条件を追加する場合も、この境界を保って追加する。

## 検証

`CatalogDiscovery.test.tsx` で検索とカテゴリの組み合わせ、リセット、略称・ドメイン検索、メニュー再表示時の状態、検索欄からのTab操作を検証する。
変更前の実装で4件の失敗を確認している。

`e2e/home-discovery.spec.ts` は390・768・1440pxで見出しの折り返し、横方向のはみ出し、リンク文字サイズ、操作領域、検索、フォーカス、axeのアクセシビリティ検査を実施する。
文字サイズ11px、閉じるボタン32px、モバイル見出しの3行折り返しを、それぞれ修正前の失敗として確認している。
スクリーンショットは検証時に `/tmp/` へ保存する。

インストール済みChromeを使用する場合は次のコマンドで検証できる。

```bash
PLAYWRIGHT_BROWSER_CHANNEL=chrome bunx playwright test e2e/home-discovery.spec.ts e2e/nav.spec.ts --project=chromium --workers=1
```
